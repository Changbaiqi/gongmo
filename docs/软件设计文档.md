## 1. 项目概述

### 1.1 项目背景

"工墨"是一款面向自由职业者、远程工作者及小型团队的**工时记录与记账一体化**移动应用。区别于市面上单一的记账软件或计时工具，工墨将两者深度融合：用户每次记录工时，自动关联对应收入；每笔账目也可关联具体工时条目，实现"时间—金钱"的双向追溯。

### 1.2 核心差异化特性

1. **工时与记账一体化**：一个入口同时完成工时记录与账目登记
2. **GitHub 云端备份**：以 GitHub 仓库作为免费云存储，记账数据定时同步至远程仓库
3. **多设备同步**：通过 GitHub 仓库实现不同设备间的数据同步与恢复
4. **通知识别**：自动监听手机通知栏，智能识别支付/扣款通知并生成手账记录

### 1.3 技术选型

| 类别 | 技术 | 说明 |
|------|------|------|
| 框架 | Flutter 3.x | 跨平台 UI 框架 |
| 语言 | Dart | Flutter 原生语言 |
| 状态管理 | GetX | 路由、状态、依赖注入一体化 |
| 本地存储 | Isar / Hive | 高性能 NoSQL 本地数据库 |
| HTTP 客户端 | Dio | 网络请求 |
| GitHub API | Octokit (REST API) | 仓库数据同步 |
| 通知监听 | NotificationListenerService (Android) / iOS 无此能力 | Android 端通知读取 |

### 1.4 目标平台

| 平台 | 优先级 | 备注 |
|------|--------|------|
| Android | P0 | 首发平台，支持通知识别 |
| iOS | P1 | 后续适配 |
| Web | P2 | 数据仪表盘展示 |

## 3. 核心功能设计

### 3.1 工时记录

#### 3.1.1 计时模式

- **正计时**：点击开始→计时→点击结束，自动计算时长
- **手动录入**：手动选择起止时间与日期

#### 3.1.2 数据模型

```dart
class WorkEntry {
  String id;                // UUID
  DateTime startTime;       // 开始时间
  DateTime? endTime;        // 结束时间（计时中则为 null）
  Duration? duration;       // 时长（结束或手动录入时计算）
  String? projectName;      // 所属项目
  String? description;      // 工作描述
  String? clientName;       // 客户名称
  double? hourlyRate;       // 时薪
  double? income;           // 关联收入（= duration * hourlyRate）
  String? financeEntryId;   // 关联账目 ID
  WorkStatus status;        // 进行中 / 已完成 / 已结算
  DateTime createdAt;
  DateTime updatedAt;
  bool isSynced;
}

enum WorkStatus { inProgress, completed, settled }
```

#### 3.1.3 工时总览

- 今日/本周/本月工时统计
- 按月视图展示每日工时分布（类似日历热力图）
- 按项目/客户维度汇总工时与收入

```dart
// 关键词匹配
const bankKeywords = [
```

#### 3.3.3 识别流程

1. 用户授权通知读取权限
2. 监听系统通知（安卓 NotificationListenerService）

5. 生成记账草稿，推送到应用内
6. 用户确认或编辑后保存

### 3.4 GitHub 云端同步

#### 3.4.1 同步架构

```
┌─────────┐        ┌─────────┐        ┌───────────────┐
│ 设备 A   │──Push──▶         │──Pull──▶  设备 B       │
└─────────┘        │ GitHub  │        └───────────────┘
                   │ Repo    │
┌─────────┐        │         │        ┌───────────────┐
│ 设备 C   │──Push──▶        │──Pull──▶  设备 D        │
└─────────┘        └─────────┘        └───────────────┘
        数据格式: JSON Lines (.jsonl)
        文件命名: gongmo_data/{device_id}/entries_2026-05.jsonl
```

#### 3.4.2 数据存储格式

```jsonl
{"id":"uuid-1","type":"work","data":{"startTime":"2026-05-26T09:00:00Z","endTime":"2026-05-26T12:00:00Z","duration":10800,"projectName":"项目A","hourlyRate":150,"income":450},"meta":{"deviceId":"abc123","timestamp":1716710400,"version":1}}
{"id":"uuid-2","type":"finance","data":{"type":"expense","amount":35.5,"category":"餐饮","description":"午餐"},"meta":{"deviceId":"abc123","timestamp":1716710500,"version":1}}
```

#### 3.4.3 同步策略

| 策略 | 说明 |
|------|------|
| **增量同步** | 仅同步变更条目，基于 `updatedAt` 时间戳 |
| **冲突解决** | 最后写入优先（Last Write Wins），冲突数据保留在 `conflicts/` 目录 |
| **定时同步** | 前台运行时每 15 分钟自动同步，后台通过 WorkManager 定时唤醒 |
| **手动同步** | 用户可随时手动触发全量同步 |
| **同步状态** | 每个条目维护 `isSynced` 标记，未同步条目以视觉标识提示 |

#### 3.4.4 GitHub 仓库结构

```
github.com/user/gongmo-backup/
├── README.md
├── config.json                    # 同步配置
├── data/
│   ├── device_a/
│   │   ├── entries_2026-01.jsonl
│   │   ├── entries_2026-02.jsonl
│   │   └── ...
│   ├── device_b/
│   │   └── ...
│   └── shared/
│       ├── categories.json        # 共享分类
│       └── projects.json          # 共享项目列表
└── conflicts/
    └── 2026-05-26/
        └── uuid-1_device_a.json   # 冲突备份
```

#### 3.4.5 安全设计

- 支持 Private 仓库（推荐）或 Public 仓库
- 使用 GitHub Personal Access Token (PAT) 认证
- Token 本地加密存储（flutter_secure_storage）
- 支持创建专用备份仓库，不污染日常开发仓库

```
用户点击"开始计时"
    │
    ▼
创建 WorkEntry (status: inProgress, startTime: now)
    │
    ▼
本地存储 + 标记 isSynced = false
    │
    ▼
用户点击"结束计时"
    │
    ▼
计算 duration = endTime - startTime
计算 income = duration * hourlyRate
    │
    ▼
自动创建 FinanceEntry (type: income, amount: income, linked workEntry)
    │
    ▼
等待下次同步 ➜ GitHub
```

### 9.2 通知识别流程

```
收到通知
    │
    ▼
NotificationListenerService.onNotificationPosted()
    │
    ▼
检查 packageName 是否在匹配白名单内
    │
    ├── 否 ➜ 忽略
    │
    └── 是 ➜ 解析通知内容
           │
           ▼
       正则提取金额 (¥123.45)
       关键词匹配类型 (消费/收入)
       提取商户名称
           │
           ▼
       创建 NotificationRecord (草稿状态)
           │
           ▼
       用户打开应用 ➜ 查看待确认列表
           │
           ├── 确认 ➜ 创建 FinanceEntry
           └── 忽略/删除
```

```
设备 A:                        设备 B:
```

## 10. 性能与优化

### 10.1 本地存储优化

- 按月份分页查询，避免全量加载
- 使用 Isar 索引加速查询（uuid, date, projectName）
- 列表使用 ListView.builder 懒加载

### 10.2 同步优化

- 增量同步：仅传输变更条目，减少网络开销
- 文件按月分片：避免单个文件过大导致 API 超时
- 失败重试机制（指数退避）：最多重试 3 次，间隔 2s/4s/8s
- 后台 WorkManager 定时调度，频率：15 分钟

### 10.3 通知解析优化

- 白名单过滤：仅处理银行/支付类 APP 通知
- 规则缓存：解析规则启动时加载到内存
- 去重机制：同一通知内容 10 分钟内不重复生成记录

## 14. 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| GitHub API 限流 (5000次/小时) | 频繁同步被限制 | 增量同步减少请求；按需手动触发全量同步 |
| iOS 无通知监听能力 | iOS 端无法自动记账 | iOS 端提供手动导入通知截图 OCR 方案 |
| 大数据量同步性能 | 月数据超过 10MB 时变慢 | 按日/周分文件存储，并行拉取 |
| 私人仓库数据泄露 | 用户隐私风险 | 支持 Token 双重绑定；仓库设为 Private |
